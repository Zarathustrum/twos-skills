# Product semantics and limits

**Documentation-derived, not live-tested unless stated.** Condensed on 2026-09-13 from the official documentation. These are operation-specific priors; inspect the actual feature/state before an untested mutation. Paths below identify sections under the official documentation root `https://writethingsdown.com/docs`.

| Topic / source section | Operational distinction |
|---|---|
| Item structure — things/anatomy, things/types | Text, type, completion/cancellation, star, tags, reminder, note, photos, formatting and indentation are separate. Headings do not create todos. Strikethrough formatting is not cancellation. Number type renumbers dynamically; numbers typed as text can become stale. |
| Parent movement — things/indent-and-reorder | Docs broadly say parents carry children. **Live tests narrow this:** expanded-parent selection/drag moved only parent; collapsed-parent selection included hidden children. Use explicit selection scope; see UI recipes. |
| Move/copy/clone — things/move-and-copy, lists/clones | Move preserves object identity; copy/duplicate creates independent records; clone syncs text/completion/tags/reminders/notes across appearances. Clone may require Plus; docs say Option-drag without Plus can fall back to MOVE. Do not test entitlement by dragging real content. |
| Sublists — lists/sublists | A separate list, not indentation. Single-item promotion uses item's text as title and collects descendants, reducing an indent level. Multi-selection promotion asks for a title and makes selections contents. Promotion/undo, inline display and child identity effects were not live-tested. Inspect results rather than infer deletion when children disappear into the sublist. |
| Hidden content — things/multi-select | Select All can include collapsed and completed items; search selection can span lists. Check membership/count before applying changes. Shift-click range and range boundaries across completed sections remain untested. |
| Sorting — lists/sorting, lists/auto-sort | View sort, manual order, auto-sort, and completed-inline/section placement differ. Auto-sort can separate a written outline according to some docs. Live manual reorder still returned chronological. Do not change sort settings just to approximate a requested item move. |
| Formatting — things/formatting | Docs describe selected text range vs whole line when no range, but only whole-item Header was live-tested. Quote/code may remove type depending on a setting. Preserve type and surrounding text when only formatting is requested. |
| Return/paste/join — things/return-join-split | Return is configurable; default creates/splits a thing, alternative inserts newline. Multiline paste may offer one thing vs per-line. Join chooses separator; Split offers detected separators. Exact caret anchoring is tested; bulk paste/join/split controls are not. |
| Days — days/today, days/carry-over | Days are date-named lists; Today changes with timezone/date. Opening app can trigger configured carry-over. Carry-over is distinct from manual Move: docs say an unfinished todo can bring its contiguous descendants regardless of type/completion. Do not run carry-over or create/browse arbitrary date lists as a supposedly inert lookup. |
| Reminders — reminders/auto-move, reminders/auto-detect | Item location and alert date are separate. Settings can couple reminder changes to moving items, and moving items to reminder changes. Moving to a day need not reschedule an alert. Natural-date text can prompt a reminder; preserve the user's intended text and don't accept extra scheduling by default. Inspect affected reminders when moving dated/reminded items. |
| Archive/trash — lists/archive, lists/trash | Archive retains content but may hide it from ordinary search. UI Trash is recoverable within retention, Empty Trash is permanent. MCP deletion descriptions differ; never assume identical recovery. |

Entitlement/source conflicts: docs disagree on Header and Auto-sort gating, default dash vs note, and board columns. Header worked in the tested account, which does not prove universal access. Prefer the current UI and account features; do not change feature switches as an exploratory fix. Desktop findings do not establish mobile/native behavior.
